# Решения и последовательность реализации

## Зафиксировано

1. Рабочее имя в коде — Flowix, как в существующих репозиториях. Новое написание бренда не меняется автоматически из-за вариантов в диктовке.
2. Сохраняем Git-историю `flowix-mvp`; новая реализация начинается в отдельной ветке и `v2/`. Старые данные и production не мигрируются этим изменением.
3. Переписываем фундамент записи и командного доступа. Не копируем старую авторизацию, не добавляем AI ради наличия AI.
4. Одно рабочее пространство является границей данных. Кадры и переходы разделены. Режим MVP — линейный screenshot playback.
5. Бизнес-гипотеза — платная командная библиотека конкретных сценариев. Замена готовых каталогов всех приложений не обещается.

## Этапы и критерии готовности

| Этап | Результат | Приёмка |
| --- | --- | --- |
| 0. Аудит и core | Текущая ветка: контракты, recorder state, replay, policy | TypeScript и тесты границ проходят; ограничения задокументированы |
| 1. Локальный сценарий | Chrome adapter, IndexedDB, реальная запись, минимальный плеер | Пользователь записывает 5–10 шагов и проходит их после перезапуска worker; ошибки видны |
| 2. Редактор и приватность | Проверка, удаление шагов, исправление hotspot, непрозрачная маска, экспорт | Очищенные изображения не содержат восстановимых оригиналов; переходы соответствуют кадрам |
| 3. Командный доступ | Auth, миграции, приватное storage, library, приглашения, роли, комментарии | Коллега открывает запись; посторонний и отозванный участник не получают новые данные; retries не дублируют шаги |
| 4. Платный пилот | Три команды, ограниченный срок и расходы, фиксированная тестовая цена | Повторное использование и реальная оплата; затем решение о расширении |

Этап 0 закончен только в пределах unit/type checks. Этапы 1–4 ещё не закончены. Сквозная запись и серверная изоляция должны быть проверены отдельно; зелёные unit-тесты не подменяют их.

## Архитектурный долг, который не переносим

Параллельные `app`/`src/app`; сетевой upload как единственное место хранения записи; постоянное сканирование всех вкладок; глобальные счётчики без устойчивого состояния; авторизация через cookie-флаг; service key на каждом запросе без воспроизводимой политики; простая копия URL под видом команды; потеря геометрии клика; квота через count-then-insert.
